# grib sync: internal note status reverts card column moves (stale grib note wins over done notes)

Found twice on card 20261102_001441 (2026-11-11 wip move, 2026-11-12 done move): PlannerStore.update_card(column=...) then `grib sync` moved the card RIGHT BACK (wip->todo, done->todo rev4). ROOT CAUSE: the card has TWO note records and sync gives the grib-internal note PRECEDENCE over everything: (1) grib note id == card id, stored in board.jsonl, status=todo, updated_at frozen at created_at 2026-11-02, board field empty; (2) the user dev-note md ~/.config/dev-notes/20261102_010844_*.md (status set to done, title matches the card, bound by title per grib design) — sync ignores it. WORKAROUND USED TO CLOSE: update_note(card_id, status=done) so grib note + card + md all agree, then sync reported 0 moved (done stuck at rev5). RULING NEEDED: which record is canonical (AGENTS.md says notes md are source of truth for status; grib behaves as if its internal note is). Fix = sync reads the bound md note status, or update_card propagates to the internal note. Every session that moves a card whose grib note was never updated gets silently reverted — the md status edit alone does NOT stop it.
