# fix(startup): a permanently missing model artifact costs 15 s of READY in autoload retry backoff

Measured 2026-11-04 on a fresh worktree at main (1ddddfed5, while landing card 20261101_144013 scope B): time_to_health_s 3.51-7.52 s but time_to_ready_s 18.55-22.61 s, against 4.51/4.51 s in the main checkout. Boot log (/tmp/opencode/startup_bench.log) attributes it precisely:

  07:21:11 Lazy-guard autoload skipped: no .slnc at <repo>/models/hf-cache/hub/
           models--Qwen--Qwen2.5-0.5B-Instruct/model.slnc
  07:21:11 Autoload attempt 1/3 failed: No .slnc or .soul file found ... retrying in 5.0s
  07:21:16 attempt 2 (10.0 s backoff)
  07:21:26 attempt 3 fails -> 'No local weights ... SLO_BOOTSTRAP_HF is off'
  07:21:26 Startup complete — server ready for requests

DEFECT A (the 15 s): `_autoload_model` retries with exponential backoff (`DEFAULT_LOAD_MAX_RETRIES=2`, `DEFAULT_LOAD_RETRY_DELAY=5.0` -> 5 s + 10 s) for EVERY failure, including permanent ones such as 'No .slnc or .soul file found'. Nothing can change between attempts (no download, no file appears), so the second and third attempts are pure dead time on the READY path. Fix: classify the load error (transient vs permanent) and only back off on transient; a permanent 'artifact absent' should fail once, immediately, and READY should not wait on it. Gate: boot with SLO_AUTOLOAD_MODEL naming a model with no local artifact -> time_to_ready_s within ~1 s of time_to_health_s, one attempt logged.

DEFECT B (why the artifact looked absent): `apps/api/server/main.py:61` pins `HF_HOME` to `<repo>/models/hf-cache`, which is gitignored, so a fresh clone or worktree has it empty. `get_model_dir`'s candidate order then never reaches the user-level cache (`~/.cache/huggingface/hub`, which DOES hold model.slnc here) because the pinned HF_HOME pre-empts candidate 1. Measured in the worktree: get_model_dir -> ~/.cache/huggingface/... with HF_HOME unset, but the booted app pins HF_HOME to the empty checkout cache and resolves to the missing path. Fix: after the HF_HOME candidate, fall back to the user-level cache before declaring the artifact absent (or make the HF_HOME pin conditional on the dir having weights).

Not a soul-index issue: the same log shows `Found 0 souls (0 parsed, 0 indexed, 0.22s)`; the scan cost was fixed by card 20261103_085029.
