# Card 074 — 0.5B HF→slnc conversion produces unverifiable model — FIXED

## Root cause (corrected — NOT a conversion bug)

`_fused_qkv_forward` (SloMultiHeadAttention) read `W_q/W_k/W_v.weight`
directly to build the fused float32 matmul. With `SLO_QUANTIZE=true` +
`free_quantized_originals=True` (loader default), `SloLinear.
free_quantized_originals()` has replaced `weight.data` with a `(1,)`
placeholder → concat `(3,)` → `matmul size 3 vs 896` in eager
`loader.load(verify=True)`. `forward_numpy` (generation) was already
quant-aware via `_fused_qkv()`; the autograd `forward` was not.
Lazy-guard autoload never hit it because it skips verify — hence only
the eager loader path failed (3× attempts). Reproduced with tiny model
too (`quantize=True + freed`).

## Fix (commit cd1574bf1, branch feat/ux-flows-library)

`_fused_qkv_forward`: if any of W_q/W_k/W_v `_quant_info is not None`,
return the three per-layer quant-aware `forward()` projections instead
of the fused float32 path (root-cause guard, fp32 path byte-identical).
