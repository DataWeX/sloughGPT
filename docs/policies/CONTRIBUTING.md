# Contributing

Thanks for helping improve SloughGPT.

## Quick start

1. **Branch** from `main` with a descriptive name.
2. **Install** from the repo root: `python3 -m pip install -e ".[dev]"` (see **QUICKSTART.md**). Optional — Colab smoke / `nbconvert`: `python3 -m pip install -e ".[notebook]"` (**`pyproject.toml`**), then **`scripts/run_colab_notebook_smoke.sh`** or **`make colab-smoke`** (**`make help`**; **README.md** *Google Colab*).
3. **Validate**:
   - `./verify.sh` and `python3 -m pytest tests/` (Python; CI subset in **`.github/workflows/reusable-ci-core.yml`**, including **`tests/test_checkpoint_utils.py`**, **`tests/test_config.py`** (**`merge_args_with_config`**, **`get_device`**), **`tests/test_domains_errors.py`**, **`tests/test_wandb_helpers.py`**, **`tests/test_sloughgpt_trainer_smoke.py`**, **`tests/test_sloughgpt_trainer_progress_callback.py`**, **`tests/test_cli_train_export_stem.py`**, **`tests/test_cli_train_api_payload.py`**, **`tests/test_training_router_kwds.py`**, **`tests/test_training_schemas.py`**, **`tests/test_lm_eval_char.py`**, **`tests/test_cli_local_soul_candidates.py`**, **`tests/test_soul_engine_conversation.py`**, **`tests/test_repo_root_package_json.py`** (root **`package.json`**, **`dev:stack`**, **`verify.sh`**, **`make test-repo-root`**), **`tests/test_sloughgpt_colab_notebook.py`**). With a **`.venv`**, you can use **`./run.sh python3 -m pytest tests/`** so the same interpreter is on **`PATH`**.
   - **`tests/test_sloughgpt_colab_notebook.py`** runs **`bash`** for **`scripts/run_colab_notebook_smoke.sh --help`**; if **`bash`** is not on **`PATH`**, that case is **skipped** (on Windows, use Git Bash, WSL, or rely on Linux/macOS CI).
   - Optional — **`tests/test_integration.py`** calls a **live** API on **`localhost:8000`** by default (see **`tests/README.md`** for env vars and **`websocket-client`**). Start the server first (e.g. **`SLO_API_PORT=8000 python3 apps/api/server/main.py`** or **`./scripts/dev-stack.sh`**); if nothing is listening, that module **skips**.
   - If you touch **repo root `package.json`** (e.g. **`dev:stack`** / **`dev-stack.sh`**): **`npm run test:repo-root`** (after **`npm install`** at repo root), **`make test-repo-root`**, or **`python3 -m pytest tests/test_repo_root_package_json.py -q`**.
   - If you touch **`apps/web/`**: `cd apps/web && npm ci && npm run ci` (lint + typecheck + Vitest + **`npm run build:clean`** — removes **`.next`** then **`next build`**; avoids flaky trace/cache issues; same as job **`test-web`**). To run **API + web** locally in one terminal: **`./scripts/dev-stack.sh`**, **`make dev-stack`**, or **`npm install` at repo root** then **`npm run dev:stack`** (see **QUICKSTART.md**).
   - If you touch **`packages/sdk-ts/typescript-sdk/`**: `cd packages/sdk-ts/typescript-sdk && npm ci && npm run ci` (job **`test-sdk-ts`**).
   - If you touch **`packages/strui/`**: `cd packages/strui && npm ci && npm run ci` (job **`test-strui`** — typecheck, Vitest, Storybook build).
   - If you touch **`packages/sdk-py/sloughgpt_sdk/`**: `python3 -m pytest tests/test_sdk.py -q` (job **`sdk-test-py`**).
   - If you change **`packages/standards/`** or schemas: `python3 scripts/validate_standards_schemas.py` (**`jsonschema`** is in **`python3 -m pip install -e ".[dev]"`**; otherwise `python3 -m pip install jsonschema`). Job **`standards-schemas`**.
4. **Open a PR** with a clear description of intent and scope (see **`.github/pull_request_template.md`**).

## Training entry points

- **`SloughGPTTrainer`** (`packages/core-py/domains/training/train_pipeline.py`): **`sloughgpt train`** and **`python3 -m domains.training.train_pipeline`** (local), API **`/training/start`**, and **`examples/quick_train.py`** / **`lora_train.py`**. It writes pure-numpy SloNet **`.soul`** checkpoints; Colab **`sloughgpt_colab.ipynb`** exposes the same stack alongside a manual **§7** loop (use one path per run). Optional full-notebook smoke: **`scripts/run_colab_notebook_smoke.sh`** or **`make colab-smoke`** (writes gitignored **`sloughgpt_colab.executed.ipynb`**; **`README.md`** documents env overrides; **`make help`** lists Makefile shortcuts). Colab regression only: **`make colab-test`**.
- **`TrainerProtocol`** / **`run_trainer_async`** (`packages/core-py/domains/training/trainer_protocol.py`): minimal typing contract for class trainers whose **`train(...)`** returns a **`dict`** (or **`TrainResult`**); **`run_trainer_async`** runs **`SloughGPTTrainer.train`** in a worker thread so async callers do not block the event loop.

Both default to the **`ModelInterface`** implementation **`domains.models.SloughGPTModel`** (other backends implement **`ModelInterface`** via **`ModelLoader`**); checkpoints are not interchangeable between drivers without aligning keys/format. **`SloughGPTTrainer.train(resume=True)`** accepts weights-only bundles (via **`checkpoint_utils`**) and full trainer **`.soul`** checkpoints; **`sloughgpt train`** and **`python -m domains.training.train_pipeline`** (module **`main`**) support **`--resume PATH`** and **`--resume-latest`**, and the module entrypoint also exposes **`--dropout`** and **`--lora-alpha`**. Local **`sloughgpt train`** loads **`config.yaml`** and merges CLI flags (**`merge_args_with_config`**). When **`vocab_size`** is omitted, the trainer sets vocabulary size from the corpus (CLI/config may still pass an explicit size).

**Resume semantics:** an explicit **`--resume PATH`** (or **`resume_path=...`**) fails loudly with a contextual error when the file is missing, uses an unsupported format, or is unreadable (corrupt/truncated) — it never silently resumes from a different file. The implicit path (**`--resume-latest`**, or **`resume=True`** without a path) instead skips unreadable checkpoints and resumes from the newest *readable* one (**`CheckpointManager.load_latest_with_path`** / **`load_latest`** / **`latest_valid_path`** warn + skip each bad file), so a crash mid-write of the newest checkpoint falls back to the previous good checkpoint. Callers that already resolved and loaded a checkpoint (e.g. crash recovery) pass the pre-loaded bundle via **`train(resume=True, resume_checkpoint=bundle)`** — it takes precedence over **`resume_path`** and bypasses all disk I/O, so the checkpoint is loaded exactly once (**`CheckpointManager.load_latest_with_path`** returns `(path, bundle)` as the single-load primitive). **`resume_checkpoint`** must be a bundle dict (as returned by **`load_from_path`** / **`load_latest_with_path`**) and requires **`resume=True`**; passing a path string instead of a dict raises a `ValueError` rather than silently re-loading from disk. Checkpoint artifacts are written atomically (temp file + rename) so a crash never leaves a truncated newest file: **`save_soul`** covers both the `.soul` binary and its `.meta.json` sidecar, and **`save_checkpoint_npz`** covers `.npz`. Orphaned in-progress temp artifacts (`*.tmp` / `*.tmp.npz`) are excluded from the resume-candidate scan, so they can never surface as a "latest" checkpoint.

### Checkpoint vocabulary (char LM)

Char-level training uses **`stoi`** (character → int), **`itos`** (int → character), and optionally **`chars`** (ordered vocabulary list). Full trainer **`.soul`** checkpoints written by **`SloughGPTTrainer.save_checkpoint`** include these so **`domains.training.lm_eval_char.evaluate_soul_char_lm`** and **`sloughgpt eval`** score text with the **same** charset as training (**`tokenizer_maps_from_bundle`** in **`checkpoint_utils.py`**). Periodic **`<dataset>_<timestamp>.soul`** checkpoints (when **`checkpoint_interval` > 0**) also embed **`stoi`** / **`itos`**. Bundles with only **`model_state_dict`** + **`training_info`** / **`config`** but **no** **`stoi`** make eval fall back to building the alphabet from the **eval file**; **`sloughgpt eval`** then warns when that may skew perplexity. Other deployment artifacts (HF **`tokenizer.save_pretrained`**, GGUF vocab chunks, **`.sou`**) encode vocabulary differently; they are not drop-in replacements for char **`stoi`**/**`itos`** without an explicit conversion step.

**Regression:** **`packages/core-py/tests/test_train_pipeline.py`** (`TestRestore`, `TestTrain::test_resume_from_soul_restores_step`, `TestTrain::test_resume_without_path_uses_latest`, `TestTrain::test_resume_explicit_corrupt_path_raises`, `TestTrain::test_resume_with_preloaded_bundle_restores_step`, `TestTrain::test_resume_checkpoint_takes_precedence_over_path`, `TestTrain::test_resume_checkpoint_non_dict_raises`, `TestTrain::test_resume_checkpoint_without_resume_raises`, `TestCheckpointManager::test_latest_valid_path_skips_corrupt_newest`, `TestCheckpointManager::test_load_latest_skips_corrupt_newest`, `TestCheckpointManager::test_load_latest_all_corrupt_returns_none`, `TestCheckpointManager::test_load_latest_with_path_*`, `TestCheckpointManager::test_candidates_exclude_tmp_artifacts`, `TestSaveCheckpoint::test_save_leaves_no_tmp_files`, `TestSaveCheckpoint::test_save_soul_meta_failure_leaves_no_partial_artifact`, `TestLoadSoulCheckpoint`) asserts **`stoi`** / **`itos`** / **`chars`** on trainer-native **`.soul`** checkpoints. Endpoint coverage for the crash-recovery contract (**`POST /recovery/recover/{job_id}`**: 404/400 on job status, 422 before any job is created for a corrupt or missing recorded path — including a recorded path that is simply absent from disk (`test_recover_recorded_path_missing_on_disk_422`), which must never silently fall back to a different checkpoint; the scan directory resolves from the job's stored request config when the store's `checkpoint_dir` column is NULL (`test_recover_checkpoint_dir_from_job_config`); the recovery job dict spreads the stored config first so explicit control fields always win; the bundle is handed to `train(resume=True, resume_checkpoint=...)` with no second disk load; fallback via **`load_latest_with_path`**; the recovered run reuses the ORIGINAL job's full trainer configuration through the same builder as `/training/start` (`test_recover_reuses_original_hyperparameters`), never a fixed subset; persistent-store writes target the ORIGINAL job's durable row — completion writes the produced checkpoint path (`test_recover_success_records_completion_on_original_job`), failure marks it failed (`test_recover_failure_marks_original_job_failed`), and cancel restores `interrupted` so it stays recoverable (`test_recover_cancel_restores_interrupted`) — never the ephemeral recovery id) lives in **`apps/api/server/tests/test_training_recovery_router.py`** (run from `apps/api/server` with the repo venv python and `PYTHONPATH=.:packages/core-py`). Job-store crash-detection semantics are covered by **`apps/api/server/tests/test_job_store.py`**: heartbeats are persisted via `datetime.now().isoformat()` ('T' separator), so stale detection must compare an ISO-format cutoff — never an SQLite `datetime(?, 'unixepoch')` string, which is lexicographically *greater* than any 'T'-separated timestamp and silently never fires (`test_detect_crashed_jobs_stale_running` is the format regression); both 'running' and 'recovering' rows are crash-detected when their heartbeat is stale, non-running statuses are never flagged; the recoverable list returns 'interrupted' + 'failed' + stale-'recovering' rows but never an actively-recovered row — `mark_recovering` stamps a fresh heartbeat (clearing `crashed`), so a just-started recovery cannot be listed as recoverable or crash-detected while alive; the endpoint guard mirrors this exactly (fresh 'recovering' → 400 `test_recover_400_when_recovering_with_fresh_heartbeat`, stale 'recovering' → 200 `test_recover_allows_stale_recovering_job`).

**`sloughgpt train` exports:** default Soul (and other format) basename under **`checkpoint.save_dir`** is **`{model}-{dataset}-{YYYY-MM-DD-HHMMSS}`**; use **`--save-stem`** for a fixed name. **`sloughgpt generate`** (local, no API) loads **`models/sloughgpt.soul`** first, then the newest **`models/*.soul`** by mtime (see **`_local_soul_candidate_paths`** in **`apps/cli/src/cli.py`**).

**HTTP training (Console / SDK):** **`POST /training/start`** in **`apps/api/server/training/`** accepts **`TrainingRequest`** JSON (including **`log_interval`** and **`eval_interval`**). Tracked jobs expose live fields via **`GET /training/jobs`** / **`GET /training/jobs/{job_id}`** (**`progress`**, **`current_epoch`**, **`global_step`**, **`train_loss`**, **`eval_loss`**). Trainer **`.soul`** files on the API host use the same char-vocab embedding rules as local **`cli.py train`** (*Checkpoint vocabulary* above). The legacy demo server in **`packages/core-py/domains/ui/api_server.py`** uses a different **`/training/start`** contract (query params, toy loop); prefer **`apps/api/server`** for parity with the web app and SDKs.
