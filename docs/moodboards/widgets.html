Widgets — live state you can act on at a glance

What could we build if every long-running thing in sloughGPT — training runs, token burn, journeys, consciousness — had a small persistent face with exactly one action?

2026-10-04 idea: widgets (from “think of widgets”) kanban a9bc8648 1 MINE · 8 evidence 2 FETCH · 10 refs, 4 visuals 3 MOCK · 3 variants 4 ASSEMBLE

The idea

Widget = a live state slice + one glanceable action. It is not a page, not a banner (transient), not a toast (confirmation) — it is the missing persistent layer: something small that keeps watching a running process and lets you jump into it without opening the dashboard. Token-themed, and loading / empty / error are part of the widget, not an afterthought.

1. live state slice (poll or SSE) 2. exactly one glanceable action 3. loading · empty · error built in 4. Noir Violet tokens only 5. one source → many surfaces

Open questions — react to these

1 · One descriptor, many projections?

Build widgets as a {state source, action, states} descriptor projected to grid / float / rail (ToolSpec pattern) — or hand-build one surface first and generalize later?

2 · Poll or stream, per widget?

useConsciousnessStatus polls; streamSSE exists for live feeds. Who owns reconnect/backoff — widget, sse-client, or http-client layer?

3 · Which 2–3 ship first?

Ready contracts: training run, token budget, consciousness mood, journey status, inference queue. Which three earn their place?

4 · Mole interplay?

Card 43ca5222 said “no widget in the web section” — Variant B (float) needs an explicit product OK, or it repeats a ruling we already made.

5 · Confirm the three-layer split

banner = blockers · toast = transient · widget = persistent glanceable. Worth writing into DESIGN_SYSTEM so future PRs stop inventing a fourth pattern.
